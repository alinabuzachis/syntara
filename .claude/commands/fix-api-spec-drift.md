description: Detect and interactively fix OpenAPI spec drift between sub-schemas and the implementation.

## Overview

This skill detects drift between the OpenAPI spec and the implementation, then guides you through fixing each issue one at a time.

**How the drift check works:**
- `src/nexus/schemas/openapi.yaml` (assembled from domain sub-specs via `make api-spec-bundle`) is the **source of truth** — it defines how the API is supposed to look.
- `uv run python tools/export_openapi.py` generates a live spec directly from the FastAPI application — this reflects what the implementation *actually* exposes right now.
- `make api-spec-drift` compares these two. Any discrepancy means the implementation has drifted away from the spec.

**Key facts:**
- `src/nexus/schemas/openapi.yaml` is **read-only** — it is generated by `make api-spec-bundle`. Never edit it directly.
- When drift is found, the fix could go into the source code (routers, models, services) to bring the implementation back in line with the spec.
- If the spec itself is wrong or outdated, fix the appropriate domain sub-spec under `src/nexus/schemas/<domain>/`. If the bundling logic is at fault, fix `tools/bundle_openapi.py`.

## Steps

1. **Run the drift check** and capture output. DO NOT summarize the output:

   ```bash
   make api-spec-drift VERBOSITY=-vv 2>&1 | tee /tmp/api-spec-drift-output-$$.txt
   ```

   Use `$$` (the shell PID) so parallel sessions don't overwrite each other's files.

2. **Ask the user which issue to fix first.** Link the file created in the previous step. DO NOT summarize it. Then wait for their answer before proceeding.

3. **For each issue the user selects:**

   a. Read both the relevant sub-spec file and the corresponding implementation (router, model, service) to understand the root cause. Establish which side is wrong:
      - **Implementation is wrong**: the FastAPI code doesn't match the spec → fix the source code (router, model, or service).
      - **Spec is wrong or outdated**: the sub-spec doesn't reflect the intended contract → fix the domain sub-spec under `src/nexus/schemas/<domain>/`.
      - **Bundling logic is wrong**: `tools/bundle_openapi.py` is mangling or dropping something → fix that file.

   b. Make the minimal targeted edit.

   c. Re-run the drift check to verify the fix:

      ```bash
      make api-spec-drift VERBOSITY=-vv 2>&1 | tee /tmp/api-spec-drift-output-$$.txt
      ```

   d. Confirm the issue is resolved, then ask the user which remaining issue to tackle next.

4. **Repeat** until the user is satisfied or no drift remains. Compact context whenever a new issue is worked on.

## Reminders

- Do **not** edit `src/nexus/schemas/openapi.yaml` — it is auto-generated.
- `src/nexus/schemas/openapi.yaml` is the source of truth. When in doubt, ask the user.
- Keep changes minimal and targeted to the specific drift reported.
- After all fixes, the user can regenerate the bundled spec with `make api-spec-bundle` and commit both any sub-spec changes and the regenerated `openapi.yaml`.
