# Formatting Standards

Pre-commit is the single source of truth for all formatting tools and their versions. Every formatter is pinned in `.pre-commit-config.yaml` and invoked through pre-commit hooks. No standalone tool invocations in the Makefile or CI should duplicate a pre-commit hook.

## Core Rule

**One tool, one version, one config.** If a formatting tool exists as a pre-commit hook, that hook is the authority. Never invoke the same tool from a different source (container image, system binary, separate pip install) — version drift between sources produces different output, causing infinite reformatting loops.

## Makefile Targets

| Target | Behavior |
|--------|----------|
| `make format` | Modifies files. Runs ruff + pre-commit formatting hooks (trailing-whitespace, end-of-file-fixer, mixed-line-ending, yamlfmt) |
| `make lint` | Verifies. Runs check-only tools first (ruff check, ruff format --check, check_file_formatting.py, mypy), then pre-commit hooks. Pre-commit hooks may modify files when drift is detected (same pattern as api-spec-bundle, generate-api-client) |

### Expected Workflow

```
make format    # fix everything
make lint      # verify — first run may update generated files (spec, client)
make lint      # second run should pass (idempotent)
```

If `make lint` fails on the first run due to spec/client regeneration, running it again confirms convergence. If it fails on the second run, there is a formatting tool conflict that must be resolved.

## Generated File Cleanup

Generated output (API client, bundled OpenAPI spec) must be cleaned at generation time by the Makefile target that produces it. Downstream pre-commit hooks cannot be relied on because they run in declaration order — hooks declared before the generator cannot clean up after it.

### API Client (`make generate-api-client`)

The `openapi-python-client` generator produces files with trailing whitespace and missing EOF newlines. The Makefile target strips these with `sed` and shell commands after generation. This is intentional:

- `sed` is version-independent — no tool version to drift
- The pre-commit `trailing-whitespace` hook with `--markdown-linebreak-ext=md` preserves trailing whitespace in `.md` files, so it cannot clean the generated `README.md`
- The generator runs inside a pre-commit hook, and re-entrant `pre-commit run` calls from within a hook are unreliable

### Bundled OpenAPI Spec (`make api-spec-bundle`)

The bundler runs `uv run pre-commit run yamlfmt` on the generated spec as a post-processing step. This ensures the committed spec matches yamlfmt's expected output, preventing drift on the next lint run.

## Adding a New Formatter

1. Add the tool as a pre-commit hook in `.pre-commit-config.yaml` with a pinned version
2. Add it to `make format` if it should run during formatting (most formatters should)
3. Do NOT add a separate invocation in `make lint` — let pre-commit handle it
4. If the tool needs to run on generated files, add a post-processing step in the relevant generator's Makefile target
5. Verify convergence: `make format && make lint && make lint` should pass on the second `make lint`

## Anti-Patterns

- **Container-based formatter in lint**: running `podman run yamlfmt:latest` when pre-commit pins `yamlfmt v0.21.0` — version drift causes infinite reformatting
- **Pre-commit hook calling pre-commit**: re-entrant `pre-commit run` from within a hook can fail silently — use direct tool invocations for post-processing within hooks
- **Relying on hook ordering for generated files**: hooks run in declaration order; a formatter declared before a generator cannot clean the generator's output
