# Data Model: Workflow Engine

**Database**: PostgreSQL 17 (REQUIRED - SQLite is not supported)
**Note**: This data model uses PostgreSQL-specific features including JSONB type and GIN indexes. All development and testing must use PostgreSQL.

## Core Entities

### Workflow
Represents a complete automation process with multiple activities. This entity tracks the current state and metadata, while version history is maintained in WorkflowVersion.

**Fields:**
- `id`: UUID (Primary Key) - **Auto-generated**
- `name`: String - **Required** (Human-readable name)
- `description`: Text - **Optional** (defaults to null)
- `labels`: JSONB - **Optional** (defaults to `{}`, key-value labels for categorization and filtering, e.g., `{"environment": "production", "team": "data-platform"}`)
- `current_version`: Integer - **Auto-set** (Current active version number, defaults to 1 on creation)
- `created_by`: UUID (Foreign Key to User) - **Required** (Set from authenticated user context)
- `created_at`: Timestamp - **Auto-generated** (Set on creation)
- `updated_at`: Timestamp - **Auto-updated** (Set on creation and every update)
- `is_enabled`: Boolean - **Optional** (defaults to `true` - workflow is enabled and available for execution)
- `deleted_at`: Timestamp - **Auto-set** (defaults to null, set when workflow is soft deleted)
- `deleted_by`: UUID (Foreign Key to User) - **Auto-set** (defaults to null, user who deleted the workflow)

**Relationships:**
- `created_by` → User (Many-to-One)
- `deleted_by` → User (Many-to-One)
- `versions` ← WorkflowVersion (One-to-Many)
- `executions` ← Execution (One-to-Many)

**Validation Rules:**
- `name` must be globally unique across all non-deleted users
- `current_version` must reference an existing WorkflowVersion
- `deleted_by` must be set when `deleted_at` is set

**Lifecycle States:**
- **Enabled** (`is_enabled = true`): Workflow is available for execution
- **Disabled** (`is_enabled = false`): Workflow exists but cannot be executed
- **Deleted** (`deleted_at IS NOT NULL`): Workflow is soft deleted

**State Transitions:**
- Created → Enabled (workflow created with `is_enabled = true` by default)
- Created → Disabled (workflow created with `is_enabled = false` if specified)
- Enabled ↔ Disabled (via PATCH endpoint to toggle `is_enabled`)
- Any state → Deleted (via DELETE endpoint, sets `deleted_at` and `deleted_by`)

### WorkflowVersion
Maintains complete version history of workflow definitions, enabling rollback and audit capabilities.

**Fields:**
- `id`: UUID (Primary Key) - **Auto-generated**
- `workflow_id`: UUID (Foreign Key to Workflow) - **Required**
- `version`: Integer - **Auto-incremented** (Version number, auto-incremented per workflow starting from 1)
- `schema_version`: String - **Required** (Schema version from YAML `schemaVersion` field, e.g., "1.0.0", "1.1.0", "2.0.0")
- `yaml_definition`: Text - **Required** (YAML workflow definition from Nexus, includes scheduling config)
- `created_by`: UUID (Foreign Key to User) - **Required** (Set from authenticated user context)
- `created_at`: Timestamp - **Auto-generated** (Set on creation)
- `change_description`: Text - **Optional** (defaults to null, description of changes in this version)
- `deleted_at`: Timestamp - **Auto-set** (defaults to null, set when version is soft deleted)
- `deleted_by`: UUID (Foreign Key to User) - **Auto-set** (defaults to null, user who deleted the version)

**Relationships:**
- `workflow_id` → Workflow (Many-to-One)
- `created_by` → User (Many-to-One)
- `deleted_by` → User (Many-to-One)
- `executions` ← Execution (One-to-Many, tracks which version was executed)

**Validation Rules:**
- `yaml_definition` must be valid YAML and conform to workflow schema
- `schema_version` must match semver format (e.g., "1.0.0") and be supported by the workflow engine
- `schema_version` must match the `schemaVersion` field in the `yaml_definition`
- `version` must be unique within a workflow and auto-increment
- `version` must be immutable once created
- `deleted_by` must be set when `deleted_at` is set
- Cannot soft delete a version that is currently in use by running executions
- Current version is determined by `Workflow.current_version` (no redundant field needed)

**Indexes:**
- `(workflow_id, version)` - Unique index for version lookups
- `(workflow_id, created_at)` - Version history queries
- `(schema_version)` - For queries filtering by schema version compatibility

### Execution
Runtime instance of a workflow with current state and history.

**Fields:**
- `id`: UUID (Primary Key) - **Auto-generated**
- `labels`: JSONB - **Optional** (defaults to `{}`, key-value labels inherited from workflow or set at execution time)
- `workflow_id`: UUID (Foreign Key to Workflow) - **Required**
- `workflow_version_id`: UUID (Foreign Key to WorkflowVersion) - **Required** (tracks exact version executed)
- `temporal_workflow_id`: String - **Auto-generated** (Temporal workflow execution ID, generated by Temporal)
- `status`: Enum - **Auto-set** (defaults to `pending`, values: pending, running, paused, completed, failed, cancelled)
- `started_by`: UUID (Foreign Key to User) - **Required** (Set from authenticated user context)
- `created_at`: Timestamp - **Auto-generated** (Set when execution record is created in database)
- `started_at`: Timestamp - **Auto-set** (Set when execution transitions from pending to running status)
- `completed_at`: Timestamp - **Auto-set** (defaults to null, set when execution reaches terminal state)
- `updated_at`: Timestamp - **Auto-updated** (Set on creation and every update)
- `input_data`: JSON - **Optional** (defaults to `{}`, initial workflow input parameters)
- `error_details`: Text - **Auto-set** (defaults to null, error information if failed)

**Relationships:**
- `workflow_id` → Workflow (Many-to-One)
- `workflow_version_id` → WorkflowVersion (Many-to-One)
- `started_by` → User (Many-to-One)
- `activities` ← ActivityExecution (One-to-Many)
- `audit_logs` ← AuditLog (One-to-Many)

**Validation Rules:**
- `status` transitions must follow valid state machine
- `started_at` must be after or equal to `created_at`
- `completed_at` must be after `started_at` (if both present)
- `temporal_workflow_id` must be unique
- `input_data` must conform to workflow input schema

**State Transitions:**
- pending → running (when execution starts)
- running → paused (when user pauses execution)
- paused → running (when user resumes execution)
- running → completed (when all activities succeed)
- running → failed (when unrecoverable error occurs)
- Any non-terminal state → cancelled (when user cancels)

**Note:** Execution remains in `running` status even when waiting for human approvals. Individual activities may be pending approval, but the workflow execution itself continues running.

### ActivityExecution
Individual activity execution within a workflow execution. Stores runtime state and a snapshot of the activity definition from the YAML workflow at execution time.

**Fields:**
- `id`: UUID (Primary Key) - **Auto-generated**
- `labels`: JSONB - **Optional** (defaults to `{}`, key-value labels inherited from execution or activity-specific)
- `execution_id`: UUID (Foreign Key to Execution) - **Required**
- `activity_name`: String - **Required** (Activity ID from YAML workflow definition, e.g., "fetch_data")
- `activity_definition`: JSON - **Required** (Snapshot of the activity configuration from YAML at execution time, including executor, config, retry policy, timeout, approval settings)
- `temporal_activity_id`: String - **Auto-generated** (Temporal activity execution ID, generated by Temporal)
- `status`: Enum - **Auto-set** (defaults to `pending`, values: pending, running, completed, failed, retrying)
- `created_at`: Timestamp - **Auto-generated** (Set when activity execution record is created in database)
- `started_at`: Timestamp - **Auto-set** (Set when activity transitions from pending to running status)
- `completed_at`: Timestamp - **Auto-set** (defaults to null, set when activity reaches terminal state)
- `updated_at`: Timestamp - **Auto-updated** (Set on creation and every update)
- `input_data`: JSON - **Optional** (defaults to `{}`, runtime input parameters passed to this activity)
- `output_data`: JSON - **Auto-set** (defaults to null, activity results set on completion)
- `error_details`: Text - **Auto-set** (defaults to null, error information if failed)
- `retry_count`: Integer - **Auto-set** (defaults to 0, incremented on each retry attempt)
- `iteration`: Integer - **Optional** (defaults to null, iteration number if activity is within a loop, 0-indexed)

**Relationships:**
- `execution_id` → Execution (Many-to-One)
- `approvals` ← Approval (One-to-Many)

**Validation Rules:**
- `activity_name` must correspond to an activity ID in the workflow YAML definition
- `started_at` must be after or equal to `created_at`
- `completed_at` must be after `started_at` (if both present)
- `retry_count` must be non-negative
- `iteration` must be non-negative if present
- `activity_definition` must contain valid activity configuration (executor, config, etc.)

### User
Platform users with different roles and permissions.

**Fields:**
- `id`: UUID (Primary Key) - **Auto-generated**
- `username`: String - **Required** (Unique username)
- `email`: String - **Required** (Unique email address)
- `full_name`: String - **Required** (Display name)
- `role`: Enum - **Required** (values: creator, approver, administrator, viewer)
- `is_active`: Boolean - **Optional** (defaults to `true`, account status)
- `created_at`: Timestamp - **Auto-generated** (Set on user creation)
- `last_login`: Timestamp - **Auto-updated** (defaults to null, updated on each login)
- `preferences`: JSON - **Optional** (defaults to `{}`, user preferences and settings)
- `deleted_at`: Timestamp - **Auto-set** (defaults to null, set when user is soft deleted)
- `deleted_by`: UUID (Foreign Key to User) - **Auto-set** (defaults to null, admin who deleted the user)

**Relationships:**
- `created_workflows` ← Workflow (One-to-Many)
- `started_executions` ← Execution (One-to-Many)
- `approvals` ← Approval (One-to-Many)
- `deleted_by` → User (Many-to-One)

**Validation Rules:**
- `username` must be unique across all non-deleted users
- `email` must be valid email format and unique across all non-deleted users
- `role` must be valid enum value
- `deleted_by` must be set when `deleted_at` is set

### Approval
Human-in-the-loop decision points that pause workflow execution at the activity level.

**Fields:**
- `id`: UUID (Primary Key) - **Auto-generated**
- `labels`: JSONB - **Optional** (defaults to `{}`, key-value labels for categorizing approvals, e.g., `{"urgency": "high", "department": "finance"}`)
- `activity_execution_id`: UUID (Foreign Key to ActivityExecution) - **Required**
- `approver_id`: UUID (Foreign Key to User) - **Required** (User assigned to review this approval)
- `status`: Enum - **Auto-set** (defaults to `pending`, values: pending, approved, rejected, expired)
- `request_data`: JSON - **Optional** (defaults to `{}`, data presented for approval)
- `response_data`: JSON - **Optional** (defaults to null, approver's response including reason, comments, and any additional structured data)
- `requested_at`: Timestamp - **Auto-generated** (Set when approval is created)
- `responded_at`: Timestamp - **Auto-set** (defaults to null, set when approver responds)
- `expires_at`: Timestamp - **Optional** (defaults to null, approval timeout calculated from activity configuration; null means no expiration)
- `notification_sent`: Boolean - **Auto-set** (defaults to `false`, set to `true` after notification sent)
- `created_at`: Timestamp - **Auto-generated** (Set on creation)
- `updated_at`: Timestamp - **Auto-updated** (Set on creation and every update)

**Relationships:**
- `activity_execution_id` → ActivityExecution (Many-to-One)
- `approver_id` → User (Many-to-One)

**Validation Rules:**
- `expires_at` must be after `requested_at` if present
- `responded_at` must be after `requested_at` if present
- `status` must be pending if `responded_at` is null
- `response_data` should be present when `status` changes from pending to approved/rejected
- `status` cannot be `expired` if `expires_at` is null

**State Transitions:**
- pending → approved (when approver accepts)
- pending → rejected (when approver rejects)
- pending → expired (when timeout reached)

### AuditLog
Comprehensive logging of all workflow activities and user actions.

**Fields:**
- `id`: UUID (Primary Key) - **Auto-generated**
- `execution_id`: UUID (Foreign Key to Execution) - **Optional** (defaults to null, nullable for system events)
- `user_id`: UUID (Foreign Key to User) - **Optional** (defaults to null, nullable for system events)
- `event_type`: Enum - **Required** (see Event Types below)
- `event_data`: JSON - **Optional** (defaults to `{}`, event-specific data)
- `timestamp`: Timestamp - **Auto-generated** (Set when log entry created)
- `correlation_id`: String - **Auto-set** (For tracing related events, auto-generated for execution events)
- `session_id`: String - **Optional** (defaults to null, Streamable HTTP session if applicable)

**Event Types:**
- Workflow Events: `workflow_created`, `workflow_updated`, `workflow_activated`, `workflow_deactivated`, `workflow_deleted`
- Execution Events: `execution_started`, `execution_completed`, `execution_failed`, `execution_cancelled`, `execution_paused`, `execution_resumed`
- Activity Events: `activity_started`, `activity_completed`, `activity_failed`, `activity_retrying`
- Approval Events: `approval_requested`, `approval_granted`, `approval_rejected`, `approval_expired`
- User Events: `user_login`, `user_logout`, `user_created`, `user_updated`, `user_deactivated`

**Relationships:**
- `execution_id` → Execution (Many-to-One, nullable)
- `user_id` → User (Many-to-One, nullable)

**Validation Rules:**
- `event_type` must be valid enum value
- `timestamp` must be present
- `correlation_id` must be present for execution-related events

## Database Schema Considerations

### Indexes
- `Workflow`: (created_by, is_enabled), (name) for global uniqueness, GIN index on (labels) for JSONB containment queries
- `WorkflowVersion`: (workflow_id, version) unique, (workflow_id, created_at), (schema_version)
- `Execution`: (workflow_id, status), (workflow_version_id), (started_by, started_at), (temporal_workflow_id) unique, GIN index on (labels) for JSONB containment queries
- `ActivityExecution`: (execution_id, status), (execution_id, activity_name), (temporal_activity_id) unique, (execution_id, iteration) for loop queries, GIN index on (labels) for JSONB containment queries
- `Approval`: (activity_execution_id, status), (approver_id, status), GIN index on (labels) for JSONB containment queries
- `AuditLog`: (execution_id, timestamp), (correlation_id), (event_type, timestamp)

### Constraints

**Unique Constraints:**
- `User.username`, `User.email` - Unique across non-deleted users
- `Workflow.name` - Unique across non-deleted workflows
- `WorkflowVersion.(workflow_id, version)` - Unique version per workflow (including deleted)
- `Execution.temporal_workflow_id` - Unique Temporal execution ID

**Foreign Key Cascade Rules (Soft Delete Approach):**
- `Workflow.created_by` → User: RESTRICT (preserve workflow ownership)
- `Workflow.deleted_by` → User: RESTRICT (preserve soft delete audit trail)
- `WorkflowVersion.workflow_id` → Workflow: RESTRICT (preserve version history)
- `WorkflowVersion.created_by` → User: RESTRICT (preserve version authorship)
- `WorkflowVersion.deleted_by` → User: RESTRICT (preserve soft delete audit trail)
- `Execution.workflow_id` → Workflow: RESTRICT (preserve execution history)
- `Execution.workflow_version_id` → WorkflowVersion: RESTRICT (preserve version reference for audit)
- `Execution.started_by` → User: RESTRICT (preserve execution history)
- `ActivityExecution.execution_id` → Execution: CASCADE (delete activity executions when execution deleted)
- `Approval.activity_execution_id` → ActivityExecution: CASCADE (delete approvals when activity execution deleted)
- `Approval.approver_id` → User: RESTRICT (preserve approval history)
- `AuditLog.execution_id` → Execution: SET NULL (preserve audit log when execution deleted)
- `AuditLog.user_id` → User: SET NULL (preserve audit log when user deleted)
- `User.deleted_by` → User: RESTRICT (preserve soft delete audit trail)

**Soft Delete Notes:**
- All DELETE operations on User, Workflow, and WorkflowVersion entities must be soft deletes (set `deleted_at` and `deleted_by`)
- Hard deletes are not permitted for entities with soft delete fields during normal operations
- Queries must filter out soft-deleted records by default (`WHERE deleted_at IS NULL`)
- Soft-deleted records remain in database for audit and recovery purposes
- Unique constraints only apply to non-deleted records

**Retention Policy for Soft-Deleted Records:**
- **Default Retention Period**: 90 days from `deleted_at` timestamp
- **Retention by Entity Type**:
  - User: 1 year (compliance and audit requirements)
  - Workflow, WorkflowVersion: 90 days (can be recovered if needed)
- **Hard Delete Process**:
  - Automated background job runs daily to identify expired soft-deleted records
  - Records older than retention period are permanently deleted via hard delete
  - Hard deletes cascade to dependent records (e.g., deleting a Workflow hard-deletes its WorkflowVersions)
  - AuditLog entries are created before hard deletion for compliance tracking
  - Hard delete operations are logged with event type `hard_delete_executed`
- **Recovery Window**: Users can recover soft-deleted records within retention period via admin API
- **Configuration**: Retention periods are configurable per environment via `RETENTION_POLICY_DAYS` config

**Check Constraints:**
- `Execution.started_at` >= `Execution.created_at` (if not null)
- `Execution.completed_at` > `Execution.started_at` (if both not null)
- `ActivityExecution.started_at` >= `ActivityExecution.created_at` (if not null)
- `ActivityExecution.completed_at` > `ActivityExecution.started_at` (if both not null)
- `ActivityExecution.retry_count` >= 0
- `ActivityExecution.iteration` >= 0 (if not null)
- `Approval.expires_at` > `Approval.requested_at` (if not null)
- `Approval.responded_at` > `Approval.requested_at` (if not null)
- Valid enum values for all status and type fields

### Performance Optimizations
- Partitioning AuditLog by timestamp for large datasets
- Separate read-only replicas for reporting queries
- Connection pooling for high-concurrency scenarios
- Caching frequently accessed workflow definitions
- GIN indexes on JSONB labels fields for efficient label filtering and containment queries (@> operator)
- Label query optimization using PostgreSQL JSONB operators (e.g., `labels @> '{"environment":"production"}'`)
