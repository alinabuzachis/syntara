## Phase 1: Setup

**Purpose**: Create the Installation model and database migration

- [ ] T001 Create Installation SQLModel in src/nexus/core/models/installation.py — simple table with `id` (UUID, PK) and `created_at` (DateTime with timezone, server default). Do NOT inherit from BaseResource. See data-model.md.
- [ ] T002 Register Installation model import in src/nexus/core/database/migrations/env.py so Alembic detects it for autogenerate
- [ ] T003 Generate Alembic migration via `alembic revision --autogenerate -m "add_installation_table"` then add custom data migration step after the autogenerated `create_table` to insert a singleton row with `uuid.uuid4()`. Mark custom code with `# CUSTOM:` comments per AGENTS.md convention. See data-model.md for pseudocode.

**Checkpoint**: Migration can be applied and the `installation` table contains exactly one row with a valid UUID.

## Phase 2: User Story 1 — Automatic Installation Identification (Priority: P1) 🎯 MVP

**Goal**: The installation ID exists in the database after initialization and the telemetry subsystem can read it.

**Independent Test**: Initialize the database, query the installation table, confirm exactly one UUID row exists. Run `make test-all` to verify model and migration tests pass.

### Tests for User Story 1

- [ ] T004 [P] [US1] Write unit tests for Installation model in tests/unit/models/test_installation.py — verify model fields, table name, that it is a SQLModel table, and that `id` is a UUID primary key
- [ ] T005 [P] [US1] Write integration test in tests/integration/telemetry/test_installation_telemetry.py — test that after migration the installation table has exactly one row with a valid UUID and a `created_at` timestamp

### Implementation for User Story 1

- [ ] T006 [US1] Add a `get_installation_id()` async function in src/nexus/telemetry/client.py that reads the installation ID from the database. It should query the `installation` table and return the UUID. Handle the case where the table is empty (log error, return None).

**Checkpoint**: Installation model exists, migration creates the singleton row, and `get_installation_id()` can read it. `make test-all`, `make lint`, and `make typecheck` pass.

## Phase 3: User Story 2 — Telemetry Integration with Derived `anonymousId` (Priority: P2)

**Goal**: The telemetry system derives a stable anonymous identifier from the installation ID and database connection coordinates, and uses it for all Segment events.

**Independent Test**: Verify that telemetry events include the correct derived `anonymousId`. Changing `db_host` or `db_name` in settings produces a different `anonymousId`.

### Tests for User Story 2

- [ ] T007 [P] [US2] Write unit tests for `derive_anonymous_id()` in tests/integration/telemetry/test_installation_telemetry.py — test determinism (same inputs → same output), test distinctness (different db_host or db_name → different output), test format (64-char hex string)
- [ ] T008 [P] [US2] Write integration tests for updated `initialize_telemetry()` in tests/integration/telemetry/test_client.py — test that after initialization the registry has a non-empty `anonymous_id`, test that `send_event()` passes the `anonymous_id` to `client.track()`

### Implementation for User Story 2

- [ ] T009 [US2] Add `derive_anonymous_id(installation_id, db_host, db_name)` function in src/nexus/telemetry/client.py — SHA-256 hash of `f"{installation_id}:{db_host}:{db_name}"`, returns hex string
- [ ] T010 [US2] Update `TelemetryClientRegistry` in src/nexus/telemetry/client.py — add `_anonymous_id: str` field, update `initialize()` to accept `anonymous_id` parameter, update `send_event()` to pass `anonymous_id` to `client.track()` and stop passing `entitlement_id` as `userId` (pass `None` for `userId`)
- [ ] T011 [US2] Update `initialize_telemetry()` in src/nexus/telemetry/client.py — call `get_installation_id()`, read `db_host` and `db_name` from `get_settings()`, derive `anonymous_id`, pass to `registry.initialize()`, log the `anonymous_id` at startup (FR-008)

**Checkpoint**: Telemetry events use the derived anonymous identifier. `make test-all`, `make lint`, and `make typecheck` pass.

## Phase 4: User Story 3 — Optional Entitlement ID (Priority: P3)

**Goal**: The `entitlement_id` is always included in telemetry event properties (empty string when not configured). It is NOT used as the Segment `userId`.

**Independent Test**: Send telemetry events with and without `NEXUS_ENTITLEMENT_ID` configured. Verify `entitlement_id` appears in event properties in both cases.

### Tests for User Story 3

- [ ] T012 [P] [US3] Write integration tests for entitlement_id handling in tests/integration/telemetry/test_client.py — test that `entitlement_id` is always present in event properties (empty string when not configured, actual value when configured), test that `userId` in `client.track()` is `None`

### Implementation for User Story 3

- [ ] T013 [US3] Update `TelemetryClientRegistry.send_event()` in src/nexus/telemetry/client.py — always inject `entitlement_id` into the event properties dict before calling `client.track()`. Use the stored `_entitlement_id` value (already available from settings).

**Checkpoint**: All telemetry events include `entitlement_id` in properties. `make test-all`, `make lint`, and `make typecheck` pass.
