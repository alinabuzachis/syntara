# Implementation Plan: Installation ID

**Branch**: `035-installation-id` | **Date**: 2026-03-13 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/035-installation-id/spec.md`

## Summary

Add a database-persisted `installation_id` (UUID) to uniquely identify each Nexus deployment. The ID is created by an Alembic migration during database initialization and used by the telemetry subsystem to derive the Segment `anonymousId`. This replaces the `entitlement_id` as the primary installation identifier; `entitlement_id` becomes an optional supplementary field included in event properties for subscription correlation.

## Design Details

### Installation Model

Simple SQLModel table — does NOT inherit from `BaseResource`:

```python
class Installation(SQLModel, table=True):
    __tablename__ = "installation"
    id: uuid.UUID = Field(primary_key=True)
    created_at: datetime = Field(sa_column_kwargs={"server_default": text("now()")})
```

### Alembic Migration

Creates table and inserts singleton row:

1. `op.create_table("installation", ...)` — autogenerated
2. `op.execute(insert(...).values(id=uuid.uuid4()))` — custom data migration

### anonymousId Derivation

```python
def derive_anonymous_id(installation_id: uuid.UUID, db_host: str, db_name: str) -> str:
    raw = f"{installation_id}:{db_host}:{db_name}"
    return hashlib.sha256(raw.encode()).hexdigest()
```

### TelemetryClientRegistry Changes

- Add `_anonymous_id: str` field
- `initialize()` accepts `anonymous_id` parameter
- `send_event()` passes `anonymous_id=self._anonymous_id` to `client.track()`
- `userId`: no longer set (pass `None`)
- Always include `entitlement_id` in event properties (empty string when not configured)

### initialize_telemetry() Changes

1. Read installation ID from database (async query)
2. Read `db_host` and `db_name` from settings
3. Derive `anonymous_id` via SHA-256
4. Pass `anonymous_id` to `registry.initialize()`
5. Log the `anonymous_id` (FR-008)
