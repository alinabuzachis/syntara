/specify Create a foundational base API spec and models that follow these conventions, so that all components can share.

**1\. API Conventions**

* **Scope:** The conventions defined in this specification MUST be applied to all shared models and code resources that are used by different components.
* **Style and Naming:**
  * **Properties:** Use camelCase for all schema property names. Provide a title and description for every property.
  * **Parameters:** Use snake\_case for all query parameter names.
  * **Backend Fields:** Mark all backend-managed fields (e.g., id, createdAt, updatedAt, deletedAt, createdBy, updatedBy, deletedBy) as readOnly.
  * **Nullability:** Explicitly set nullable: true for any property that can be unset.
  * **Required Fields:** Ensure all properties in base resources are marked as required unless specified otherwise.
* **Filtering:**
  * **General Rule:** All query parameters used for filtering resources MUST adhere to the conventions outlined below.
  * **Combining Filters (AND):** When multiple different filter parameters are used (e.g., ?name\[contains\]=spec\&status=active), they are combined with a logical AND.
  * **Multiple Values (OR):** To filter a single field against multiple values, you can either provide a comma-separated list (?name=abc,def) or repeat the parameter (?name=abc\&name=def). Both methods are treated as a logical OR.
  * **Operator Support:** Filtering is performed using bracket notation (e.g., parameter\_name\[operator\]=value). For the name parameter specifically, a direct equality shorthand (name=value) is also supported, which is equivalent to name\[eq\]=value. For all other filter parameters, the bracket notation is required (e.g., created\_at\[gt\]=...). Supported operators include eq, contains, gt, gte, lt, lte.

**2\. Component Schemas (/components/schemas):**

* **BaseResource**:
  * id: (string, format: uuid, readOnly)
  * createdAt: (string, format: date-time, readOnly)
  * updatedAt: (string, format: date-time, readOnly)
  * labels: (array of strings, nullable)
* **NamedResource**: Composed using allOf with BaseResource.
  * name: (string, required)
  * description: (string, nullable)
* **SoftDeletableResource**: Composed using allOf with BaseResource.
  * deletedAt: (string, format: date-time, readOnly, nullable)
  * deletedBy: (string, format: uuid, readOnly, nullable)
* **UserOwnedResource**: Composed using allOf with BaseResource.
  * createdBy: (string, format: uuid, readOnly)
  * updatedBy: (string, format: uuid, readOnly, nullable)
* **Resource**: A composite schema using allOf to combine NamedResource, SoftDeletableResource, and UserOwnedResource.
* **Error**:
  * error: (string, required)
  * message: (string, required)
  * details: (string, nullable)
* **ResourcesResponseBase**: The base for paginated responses.
  * next: (string, format: uri, nullable, title: Next Page Link, example: "/api/v1/resources?limit=20&offset=20")
  * prev: (string, format: uri, nullable, title: Previous Page Link, example: "/api/v1/resources?limit=20&offset=0")
  * total: (integer, nullable, title: Total Items, description: "The total number of items available. Only included when include\_total=true.")
* **ResourcesResponse**: Composed using allOf with ResourcesResponseBase.
  * resources: (array of Resource objects)

**3\. Component Parameters (/components/parameters):**

* **limitParam**: In query, name limit, type integer, default 20\.
* **sortParam**: In query, name sort, type string, description "Sort order, e.g., name for ascending, \-name for descending."
* **nameFilterParam**: In query, name "name". This parameter filters by resource name and adheres to the standard API Filtering conventions.
* **includeTotalParam**: In query, name include\_total, type boolean, default false, description "Set to true to include the total number of items in the response."

**4\. Example Path (/paths):**

* Create a /resources path with a GET operation.
* The operation should reference limitParam, sortParam, nameFilterParam, and includeTotalParam.
* The 200 OK response should return a JSON object using the ResourcesResponse schema.
* The default error response should use the Error schema.
